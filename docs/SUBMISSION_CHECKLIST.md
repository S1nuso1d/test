## 2. Два выбранных товара

По сообщению работодателя разрешено выбрать любые два товара из YML-фида СОЮЗ-ПРИБОР. Для тестирования выбраны две разные категории:

1. ОВЕН ДТС024-100П.В3.30/1 — термопреобразователь сопротивления, код товара 35481.
2. ОВЕН ПД100-ДИ4,0-185-0,5 — преобразователь давления, код товара 65403.

JSON-файлы:
- `examples/product_oven_dts024_100p_v3_30_1.json`
- `examples/product_oven_pd100_di4_0_185_0_5.json`

Источники, переносимые значения и намеренно исключённые неоднозначные параметры описаны в `docs/PRODUCT_SOURCES.md`.

**Проверить в скачанном XML, что обе модели есть в фиде.** Сам фид в среде подготовки репозитория напрямую не загрузился, поэтому для финального подтверждения используется PowerShell-команда из `docs/PRODUCT_SOURCES.md`. Только после совпадения обеих моделей запускай скрипт с флагом `--confirm-assignment-products`.

## 3. Реальная генерация и ручная проверка

- [ ] Подтвердить обе позиции по YML-фиду.
- [ ] Запустить Ollama и загрузить используемую модель.
- [ ] Установить зависимости и запустить FastAPI.
- [ ] Выполнить генерацию по двум выбранным JSON:

```powershell
python scripts/run_submission_check.py --products examples/product_oven_dts024_100p_v3_30_1.json examples/product_oven_pd100_di4_0_185_0_5.json --confirm-assignment-products
```

- [ ] Проверить `examples/results/submission_report.md`.
- [ ] Проверить каждый SEO-заголовок (до 70 символов) и SEO-текст (800–1200 символов).
- [ ] Проверить 3–5 поисковых запросов на отсутствие повторов.
- [ ] Сверить технические характеристики с исходной карточкой/паспортом.
- [ ] Разобрать все замечания факт-аудита, `validation_errors`, `needs_review` и признаки резервного текста.
- [ ] Проверить естественность и полезность коммерческого блока.
- [ ] Сохранить настоящие JSON- и Markdown-ответы скрипта.
- [ ] Сделать скриншоты интерфейса и результата, если решено приложить их к письму.

## 5. Ограничения, которые важно не скрывать

- Проверка чисел, единиц и выбранных рискованных утверждений эвристическая; она не доказывает семантическую достоверность всего текста.
- Класс допуска для выбранной модификации ДТС024 на странице не конкретизирован одним значением.
- Для ПД100 в карточке магазина есть несоответствия в кратком и подробном блоках по присоединению и сопротивлению нагрузки; поля исключены из исходного JSON.
- PDF-парсер извлекает текст, но не выполняет OCR для сканов.
- Поисковые запросы генерируются моделью и не сверяются с реальными объёмами поискового спроса.
- Прототип создаёт черновики и не публикует карточки автоматически.
- Цена и наличие не включены в исходные JSON, поскольку динамичны и не нужны для генерации описания.
