https://github.com/S1nuso1d/test

Разработал локальный прототип на Python, FastAPI и Ollama. Сервис принимает данные о контрольно-измерительном приборе через веб-форму или JSON и формирует черновик B2B-карточки: SEO-заголовок и описание, технические характеристики, поисковые запросы и коммерческий блок для менеджера. Реализованы экспорт JSON/Markdown, пакетная обработка, импорт CSV/XLSX, извлечение текста из PDF-паспортов и сравнение локальных моделей.

Основное архитектурное решение — не поручать LLM переписывание технических характеристик: они переносятся непосредственно из исходных данных Python-кодом. Для сгенерированного текста предусмотрены формальные проверки, аудит части рискованных утверждений и ограниченные повторные попытки исправления. Если проверку пройти не удалось, результат возвращается как черновик с предупреждениями, а резервный SEO-текст отдельно маркируется и требует ручной проверки.

Основная сложность заключалась в том, чтобы совместить заданные ограничения SEO с сохранением технических фактов и не допустить появления неподтверждённых характеристик. Поэтому я разделил генерацию текста и перенос технических параметров, добавил локальные проверки и явно обозначил ограничения эвристического контроля. В README описаны устройство проекта, промпт, запуск, принятые решения и дальнейшие улучшения.

Отдельно отмечу входные данные: в PDF говорится о двух товарах, но полный пример JSON в полученном документе приведён только для манометра DM 02. Чтобы не выдумывать второй исходный товар, я подготовил дополнительный внешний демонстрационный пример ОВЕН ПД100И по опубликованным руководствам производителя и явно отделил его от данных задания. Если второй товар передавался отдельным файлом или сообщением, буду признателен за повторную отправку — тогда смогу приложить результат именно по нему.

При необходимости готов дополнительно предоставить короткую запись экрана или скриншоты работы прототипа.

## Перед отправкой

1. Запусти проект и выполни реальную генерацию по двум доступным JSON, чтобы появились файлы в `examples/results/`.
2. Проверь `submission_report.md` и оба результата вручную. Не прикладывай результаты со статусом `needs_review`, резервным SEO-текстом или неподтверждёнными утверждениями без пояснения.
3. Если работодатель пришлёт второй товар, используй его вместо внешнего примера ОВЕН и повтори проверку.
4. Прикрепи к письму ссылку на репозиторий. Скриншоты или короткая запись экрана необязательны; их можно добавить как наглядное дополнение.
