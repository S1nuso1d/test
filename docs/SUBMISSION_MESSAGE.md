https://github.com/S1nuso1d/test

Разработал локальный прототип на Python, FastAPI и Ollama. Сервис принимает данные о контрольно-измерительном приборе через веб-форму или JSON и формирует черновик B2B-карточки: SEO-заголовок и описание, структурированные технические характеристики, поисковые запросы и коммерческий блок для менеджера. Также реализованы пакетная обработка, импорт CSV/XLSX, извлечение текста из PDF-паспортов, экспорт JSON/Markdown и сравнение локальных моделей.

В качестве входных данных выбрал две позиции из предоставленного каталога СОЮЗ-ПРИБОР: термопреобразователь ОВЕН ДТС024-100П.В3.30/1 и преобразователь давления ОВЕН ПД100-ДИ4,0-185-0,5. В репозитории приложены исходные JSON и ссылки на карточки товаров.

Основное архитектурное решение — технические характеристики переносятся из входных данных программно, а LLM используется для подготовки SEO-текста и коммерческого блока. После генерации выполняются проверки формальных требований, числовых значений и части рискованных утверждений. При обнаружении проблем приложение пытается исправить результат, а если это не удаётся — возвращает черновик с замечаниями, не маскируя его под готовый к публикации текст.

При подготовке исходных данных я также обратил внимание на неоднозначности в карточке ПД100: для присоединения и сопротивления нагрузки в разных блоках страницы указаны разные значения. Я не стал выбирать одно из них без подтверждения и исключил спорные поля из входного набора. Это отражено в документации проекта.

В README описаны установка и запуск, API, архитектурные решения, промпт, ограничения и дальнейшие улучшения. Буду рад ответить на вопросы и при необходимости показать короткую демонстрацию работы прототипа.

## Перед отправкой

1. Скачай YML-фид по ссылке из задания и проверь, что обе выбранные модели присутствуют в XML. Команда проверки находится в `docs/PRODUCT_SOURCES.md`.
2. Запусти Ollama и веб-приложение, затем выполни реальную генерацию:

```powershell
python scripts/run_submission_check.py --products examples/product_oven_dts024_100p_v3_30_1.json examples/product_oven_pd100_di4_0_185_0_5.json --confirm-assignment-products
```

3. Открой `examples/results/submission_report.md`, оба JSON и Markdown-файла. Проверь длину SEO-полей, сохранность характеристик и все предупреждения. Если есть `needs_review`, резервный SEO-текст или неподтверждённые утверждения, разберись с ними до отправки.
4. При желании приложи 2–3 скриншота интерфейса и готовых карточек. Запись экрана в письме не обязательна.

Флаг `--confirm-assignment-products` используй только после проверки, что оба выбранных товара действительно присутствуют в XML-фиде работодателя.
