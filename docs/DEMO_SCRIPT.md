# Сценарий демонстрации Product Copy AI

Цель демонстрации — за 3–5 минут показать не просто генерацию текста, а полный путь от исходных технических данных до проверяемого черновика.

## Перед демонстрацией

1. Установить зависимости по README и запустить Ollama.
2. Убедиться, что выбранная модель уже загружена.
3. Запустить приложение командой `uvicorn app.main:app --reload`.
4. Открыть `http://127.0.0.1:8000` и нажать «Проверить модель».
5. Использовать DM 02 из задания. Для дополнительного второго сценария можно использовать внешний пример ОВЕН ПД100И из examples/product_owen_pd100i_external_demo.json; он основан на официальном руководстве, но не был предоставлен работодателем. Не выдавать синтетический TP-200 за второй товар задания.

## Порядок показа

### 1. Входные данные

Показать простую форму и JSON-режим. Отдельно выделить исходные факты DM 02: диапазон измерений 0–1,6 МПа, класс точности 1,5, присоединение G1/2 и диаметр корпуса 100 мм.

### 2. Генерация

Сгенерировать карточку и показать четыре результата: SEO-заголовок, SEO-описание, поисковые запросы и коммерческий блок. Проверить длину SEO-полей и количество запросов.

### 3. Контроль достоверности

Показать, что характеристики формируются из входного JSON, а не переписываются моделью. Продемонстрировать диагностические сообщения на отдельном тестовом примере, где диапазон 0–1,6 МПа ошибочно сокращён до «до 1,6 МПа». Такой пример должен быть помечен как тест ошибки, а не как правильный результат.

### 4. Импорт и пакетный режим

Показать импорт CSV/XLSX. Импорт PDF демонстрировать только на текстовом PDF с простыми строками «параметр: значение»; проговорить отсутствие OCR и необходимость проверки паспорта. Пакетную генерацию можно показать на DM 02 и внешнем примере ОВЕН ПД100И, отдельно оговорив источник второго набора. Синтетический TP-200 явно называть синтетическим.

### 5. Результат и воспроизводимость

Показать экспорт JSON/Markdown, README, автоматические тесты и GitHub Actions. Для двух входов из задания сохранить фактические результаты в `examples/results/` с помощью `scripts/run_submission_check.py`.

## Что нельзя заявлять

- Что все галлюцинации исключены.
- Что PDF-парсер одинаково хорошо разбирает любые паспорта.
- Что локальные тесты доказывают качество ответа каждой модели.
- Что формальный quality score равен вероятности достоверности.
- Что синтетический TP-200 — один из товаров задания.

Главный тезис демонстрации: система не только генерирует черновик, но и показывает контент-менеджеру, какие части требуют проверки, при этом не подменяет исходные технические характеристики текстом модели.
