# Product Copy AI v0.4.0

Локальный AI-помощник для подготовки черновиков карточек контрольно-измерительных приборов для B2B-интернет-магазина. Основа приложения — FastAPI и Ollama; облачный API-ключ не требуется.

## Возможности

- Ввод одного товара или JSON-массива до 10 товаров через веб-интерфейс и REST API.
- Локальная генерация через Ollama Python SDK и структурированный JSON Schema output.
- SEO-заголовок до 70 символов, SEO-описание 800–1200 символов, 3–5 поисковых запросов и структурированный коммерческий блок.
- Технические характеристики копируются приложением непосредственно из входного JSON; LLM их не переписывает.
- До трёх попыток генерации с передачей модели конкретных ошибок проверки.
- После трёх неудачных попыток лучший черновик возвращается со статусом `needs_review`, списком нарушений и предупреждением. Он не выдаётся за готовую карточку.
- Проверка числовых значений во всех генерируемых текстовых полях: заголовке, описании, запросах и коммерческом блоке.
- Определение недостающих характеристик по категории прибора (манометр, преобразователь температуры/давления, датчик температуры, расходомер, датчик уровня). Неизвестная категория не получает случайный универсальный список требований.
- Отчёт о пустых полях, пустых характеристиках и ожидаемых, но не указанных параметрах.
- Экспорт результата в JSON и Markdown; пакетный экспорт через веб-интерфейс.
- Обработка ошибок подключения, отсутствующей модели, неверного JSON и недостатка исходных данных.

## Требования

- Python 3.11 или новее.
- Установленный и запущенный [Ollama](https://ollama.com/download).
- Загруженная модель. По умолчанию используется `qwen2.5:14b`.

## Установка на Windows

```powershell
ollama list
ollama pull qwen2.5:14b

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[dev]"
Copy-Item .env.example .env
```

При необходимости отредактируйте `.env`:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:14b
OLLAMA_TIMEOUT_SECONDS=300
OLLAMA_NUM_CTX=8192
OLLAMA_NUM_PREDICT=2200
OLLAMA_KEEP_ALIVE=5m
```

Файл `.env` исключён из Git. Для локального Ollama API-ключ не нужен.

## Запуск

```powershell
uvicorn app.main:app --reload
```

- Веб-интерфейс: http://127.0.0.1:8000/
- Swagger: http://127.0.0.1:8000/docs
- Health: http://127.0.0.1:8000/health
- Статус модели: http://127.0.0.1:8000/api/status

Нажмите «Проверить подключение Ollama», затем отправьте JSON товара. Для пакетной генерации передайте в поле ввода массив из 1–10 товаров.

## REST API

- `POST /api/generate` — один товар.
- `POST /api/generate/batch` — пакет до 10 товаров; обработка последовательная, чтобы не перегружать локальную модель.
- `POST /api/test-connection` — тестовый запрос к модели.
- `POST /api/export/markdown` — преобразование результата генерации в Markdown.

В товар можно добавить необязательное поле `category`, например `pressure_gauge`, `temperature_transmitter`, `pressure_transmitter`, `temperature_sensor`, `flow_meter` или `level_sensor`. Если поле не указано, приложение пытается определить категорию по названию и описанию. Для неизвестной категории специфические характеристики не навязываются.

Пример входных данных:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "category": "pressure_gauge",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Это пример из иллюстрации тестового задания, а не полный паспорт реального товара.

## Статусы ответа

- `generated` — форматные проверки пройдены; карточка всё равно остаётся черновиком и требует редакторской проверки.
- `needs_review` — после трёх попыток остались ошибки. Черновик и точные замечания возвращаются пользователю, но публикация без проверки не рекомендуется.
- `needs_data` — исходной информации недостаточно даже для осмысленного запроса к LLM.

## Проверка

```powershell
python -m pytest -q
```

Тесты проверяют категорийные шаблоны недостающих характеристик, перенос исходных значений, ограничения SEO-полей, числовую проверку во всех генерируемых текстах, повторные попытки, статус ручной проверки, пакетный API и Markdown-экспорт. Тесты не требуют реального подключения к Ollama: SDK изолирован моками. Качество текста и скорость необходимо дополнительно проверить на локальной модели.

## Промпт и защита от недостоверных сведений

Системный промпт запрещает придумывать технические характеристики, конвертировать единицы и выполнять инструкции, попавшие в название или описание товара. Исходный JSON помещается в отдельный блок `<product_data>` и трактуется как недоверенные данные.

Технические характеристики в ответе формирует Python-код напрямую из исходного JSON. LLM отвечает за SEO-текст, поисковые запросы и коммерческий блок. Локальный валидатор проверяет длину полей, число запросов и наличие новых числовых токенов во всех сгенерированных текстовых полях. При ошибках приложение передаёт модели конкретный список замечаний и повторяет генерацию до трёх раз.

Проверка чисел — только эвристика. Она не выявляет все смысловые галлюцинации: например, неподтверждённое утверждение без чисел может пройти. JSON Schema подтверждает структуру, а не фактическую достоверность. Результат обязательно должен проверяться человеком перед публикацией.

## Ограничения и дальнейшие улучшения

- Категорийные шаблоны характеристик эвристические; их нужно согласовать с каталогом конкретного производителя и типами приборов.
- Проверка чисел не является полной семантической проверкой и не доказывает соответствие числа конкретной характеристике или единице измерения.
- Нет базы данных, авторизации, истории генераций, CMS и публикации карточек.
- Пакетная обработка выполняется последовательно; параллельный режим не включён, чтобы не перегружать локальную модель.
- Поисковые запросы генерируются LLM и не подтверждаются реальными объёмами поиска.
- Для следующего этапа можно добавить сопоставление каждого утверждения с источником, извлечение сведений из PDF-паспортов, каталог утверждённых терминов и golden dataset с экспертно проверенными карточками.

## Выполнение тестового задания

В приложенном к задаче PDF приведён пример одного товара. Полные исходные данные второго товара в PDF отсутствуют. Файл-пример второго прибора нельзя выдавать за предоставленные работодателем данные: перед финальной сдачей нужно подставить реальный второй набор характеристик и сохранить фактические результаты генерации.
