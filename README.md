# Product Copy AI

MVP AI-помощника для подготовки черновиков карточек контрольно-измерительных приборов для B2B-интернет-магазина. Проект использует локальную LLM через Ollama: API-ключ, платная облачная подписка и передача карточек товара внешнему провайдеру не требуются.

## Возможности

- Принимает данные товара в JSON через REST API и простую веб-страницу.
- Подключается к локальному Ollama через официальный Python SDK.
- Использует JSON Schema / Structured Outputs для получения структурированного ответа.
- Формирует SEO-заголовок до 70 символов, SEO-описание 800–1200 символов, 3–5 поисковых запросов и коммерческий блок.
- Копирует технические характеристики непосредственно из исходного JSON: LLM не генерирует значения этого раздела.
- Проверяет длину и структуру полей, повторяет генерацию при нарушении формальных требований.
- Проверяет новые числовые значения в SEO-описании и коммерческом блоке и просит модель исправить неподтверждённые числа.
- Показывает отсутствующие поля и предупреждает о необходимости проверки черновика.
- Имеет кнопку проверки локального сервера и выбранной модели.
- Обрабатывает ошибки подключения, отсутствующую модель, невалидный JSON и недостаток входных данных.

## Требования

- Python 3.11 или новее.
- Установленный и запущенный [Ollama](https://ollama.com/download).
- Загруженная локальная модель. В конфигурации по умолчанию используется `qwen2.5:14b`.

## Подготовка Ollama

Проверьте наличие модели в PowerShell:

```powershell
ollama list
```

Если `qwen2.5:14b` отсутствует, загрузите её:

```powershell
ollama pull qwen2.5:14b
```

Убедитесь, что локальный API доступен:

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Стандартный адрес локального Ollama API — `http://127.0.0.1:11434`.

## Установка (Windows PowerShell)

Распакуйте проект и откройте PowerShell в каталоге `product_copy_ai`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[dev]"
Copy-Item .env.example .env
```

При необходимости измените `.env`:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:14b
OLLAMA_TIMEOUT_SECONDS=300
OLLAMA_NUM_CTX=8192
OLLAMA_NUM_PREDICT=2200
OLLAMA_KEEP_ALIVE=5m
```

**API-ключ не нужен.** Файл `.env` исключён из Git и хранит только локальные настройки приложения.

### Настройка под компьютер

Начальная конфигурация рассчитана на локальную генерацию с контекстом 8192 токена. На видеокарте с 12 ГБ VRAM модель `qwen2.5:14b` может частично размещаться в оперативной памяти, поэтому скорость зависит от квантования модели и доступной RAM. При нехватке памяти можно попробовать более компактную установленную модель или уменьшить `OLLAMA_NUM_CTX` до `4096`.

## Запуск

Убедитесь, что Ollama запущен, затем выполните:

```powershell
uvicorn app.main:app --reload
```

Откройте в браузере:

- Веб-интерфейс: http://127.0.0.1:8000/
- Swagger API: http://127.0.0.1:8000/docs
- Проверка состояния приложения: http://127.0.0.1:8000/health
- Настройки локальной модели: http://127.0.0.1:8000/api/status

В интерфейсе нажмите **«Проверить подключение Ollama»**. Приложение отправит короткий запрос выбранной локальной модели. После успешной проверки можно нажать **«Сгенерировать карточку»**.

## Пример запроса

`POST /api/generate`

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Пример входных данных взят из иллюстрации в тестовом задании. Это не следует считать полным паспортом реального товара.

## Проверка

```powershell
python -m pytest -q
```

Автотесты проверяют копирование исходных характеристик, обработку пустых данных, эвристическую проверку чисел, повторную попытку при нарушении требований к SEO-полям и работу клиента Ollama на изолированном тестовом SDK. Для проверки реального качества текста нужно запустить локальный Ollama и выполнить генерацию через веб-интерфейс.

## Промпт и принятые решения

Системный промпт задаёт роль B2B-редактора и запрещает добавлять характеристики, диапазоны, материалы, питание, интерфейсы, сертификаты, комплектацию и другие сведения, которых нет во входном JSON. Данные товара явно объявляются недоверенным содержимым, а не инструкциями модели.

Технические характеристики формируются приложением непосредственно из исходного JSON, а не генерируются LLM. Это исключает изменение значения характеристики моделью в отдельном структурированном блоке.

Ollama получает JSON Schema Pydantic-модели через параметр `format`. После разбора приложение отдельно проверяет ограничения задания: длину SEO-заголовка и описания, количество поисковых запросов. При ошибке формата или неподтверждённых числах делается одна повторная попытка.

Для SEO-описания и коммерческого блока применяется дополнительная эвристическая проверка чисел. Она выявляет числовые значения, которых нет в источнике, и просит модель исправить черновик. Это не является полноценной семантической проверкой фактов: человеческая проверка перед публикацией обязательна.

## Ограничения и дальнейшие улучшения

- Локальная модель может медленнее облачной модели генерировать длинные тексты, особенно если часть модели размещается в RAM.
- Проверка чисел не гарантирует отсутствие неподтверждённых текстовых утверждений без числовых значений.
- Структурированный ответ по JSON Schema не гарантирует фактическую достоверность содержания.
- В текущем MVP нет базы данных, авторизации, CMS, сохранения истории и публикации карточек.
- Нет автоматического получения характеристик из технических PDF-паспортов и каталога производителя.
- Можно добавить извлечение фактов из PDF, сопоставление каждого предложения с источником, пакетную генерацию, оценку качества SEO, историю версий и альтернативные LLM-провайдеры.
- Для завершения тестового задания необходимо подставить исходные данные второго товара и сохранить фактические результаты генерации. В приложенном PDF приведён пример одного товара, а не два полных набора данных.
